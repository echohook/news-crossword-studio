# 選題排序與重點新聞 — v1.2.0

Solver 現在會主動嘗試涵蓋候選中的 Anchor Event，並比較搜尋得到的合法方案。獨立 Validator 的 V01～V08 維持幾何檢查，不把新聞重要性當成盤面合法性。

## 方案比較順序

1. 題數較多者優先，最高仍由 target 限制。
2. 同題數時，8×8 優先於 9×9，再優先於 10×10。
3. 同題數、同尺寸時，涵蓋更多重點「事件」者優先。
4. 其次優先符合單一字數不超過 50% 的方案。
5. 再比較 2／3／4 字分布與平均目標的差距。
6. 前述條件全部相同時，比較編輯評分。

因此，8×8 全題數盤不會只為了多一則重點新聞而自動改選 9×9。即使某個不合法盤涵蓋更多新聞，也不會進入方案比較。

涵蓋率按事件計數；同事件選兩題只算一次。任一候選把某事件標記為重點，選入該事件的另一個候選也算涵蓋。

## 標記方法

本機新聞管線使用事件欄位：

```json
{"event_id":"important-news","anchor_event":true}
```

直接送入 Solver 的候選可保存 event.anchor_event=true，或在候選上設定 anchor_event=true。只有布林 true 表示重點，字串 "false" 或 "true" 不視為標記。

編輯評分使用 70% Answer Score + 30% Event Score 的候選平均值。直接 Solver 的可選評分欄位若缺少、非有限數字或不在 0～100，排序時算零；新聞管線仍先執行原有最低分及格式檢查。這個評分不能判定新聞真假或題目唯一性。

## 搜尋與報告

搜尋過程先嘗試能新增重點事件的合法交叉，再以字數不足項目、固定種子的探索與少量評分偏好選擇下一步。所有完成方案仍重新送入獨立 Validator。

Solver JSON 新增 selection_order、selection_quality、selection_warnings，並在每個尺寸的 diagnostics 保存最佳方案品質。CLI 顯示候選重點事件涵蓋率、字數差距、編輯評分及缺漏原因。

新聞管線另顯示「本期合格重點新聞涵蓋」：分母包括已通過事件檢查、但因沒有題目或題目不合格而無法進入 Solver 的事件。這些事件仍出現在 missing_anchors，不能藉由候選篩選隱藏漏題。連 NO_ELIGIBLE_CANDIDATES 也保存此報告。

- ANCHOR_NO_SHARED_CHARACTER：該事件所有候選都無共同字，無法滿足至少一個交叉，需要擴充候選。
- ANCHOR_NOT_SELECTED：本次方案沒選入，可能是尺寸、題數或有界搜尋的取捨，不宣稱已證明無解。
- ANCHOR_TARGET_LIMIT：重點事件數多於目標題數，不可能在此題數下每件至少選一題。

有界啟發式搜尋沒有全域最優保證。找到全題數、涵蓋所有候選重點事件且字數差距已達理論最小值時，可提早結束；此時不宣稱編輯評分也全域最優。

## 可重複驗收

```powershell
node cli.mjs pipeline examples/news-real-20261001.json
node cli.mjs pipeline examples/news-real-20261001.json --attempts 256 --seed 2
node cli.mjs batch examples/selection-batch.json
npm test
```

本版預設設定在真實新聞快照上得到 8×8、12 題、兩則重點全入盤，字數分布 3／5／4。增加搜尋預算並使用既有 seed 2 設定，同樣得到 3／5／4，兩則重點同樣全入盤。它們都是本固定資料與版本的實測結果，其他題庫不保證相同。

新增 12 項測試，包含事件只計一次、選題比較順序、評分取捨、無共同字的重點候選、題數不足、預設種子的真實快照、候選被排除但新聞仍須報告等。當時版本總共 **104 項測試**；v1.5.0 累計 146 項。
